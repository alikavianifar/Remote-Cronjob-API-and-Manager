🛡️ Security & Stability Features

SECURITY No shell for crontab access The crontab binary is started with child_process.spawn and an argument list, and the new table is sent over stdin. Job text is never interpolated into a shell command line, and line breaks are rejected.
AUTH JWT, rate limits, production guard Every endpoint except the health check needs a token. Login is rate-limited, and in production the server refuses to start without a strong JWT_SECRET and ADMIN_PASSWORD.
STABILITY Managed block, safe rollback Jobs live in a marked block of the user's crontab; every other line is left untouched. If writing the crontab fails, the stored change is rolled back so both stay consistent.
OPERATIONS Force run with logs Force Run executes the command with a timeout and an output limit, then stores stdout, stderr, exit code and duration. Runs started by cron itself are not captured.

🚀 Technical Highlights

  • Native Integration: Uses the OS's native crontab. If the Node.js API crashes, your scheduled jobs keep running.
  • Zero Migration: Drop-in solution for existing servers. No need to rewrite scripts or move to Docker containers.
  • Single source of truth: The application's data file holds the jobs and the crontab is generated from it. Edits made by hand inside the managed block are overwritten on the next change.
